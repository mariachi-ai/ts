'@mariachi/auth-cognito': minor

New `@mariachi/auth-cognito`: an Amazon Cognito user pool as the auth port's provider. `createCognitoAuth` verifies ID and access tokens against the pool's JWKS (RS256, the pool's issuer, `token_use`, and `aud` or `client_id` for the app client), mapping `cognito:groups` to roles and `scope` to scopes. `createCognitoIdentityClient` implements `IdentityClient`: managed login (`authorizationUrl` with PKCE, `exchangeCode`, `refresh` and `signOut` with token revocation at the pool's domain, plus `logoutUrl`), password sign-in through InitiateAuth `USER_PASSWORD_AUTH` with `SECRET_HASH` for a confidential client, and users through the admin API (AdminGetUser, ListUsers, AdminCreateUser, AdminSetUserPassword, AdminDeleteUser), signed with SigV4 by `@aws-sdk/client-cognito-identity-provider`, an optional peer. Every call goes through `callProvider`, settings come from `contract.json` (`COGNITO_REGION`, `COGNITO_USER_POOL_ID`, `COGNITO_CLIENT_ID`, `COGNITO_CLIENT_SECRET`, `COGNITO_DOMAIN`, and optional AWS keys), and `@mariachi/auth-cognito/testing` has a token issuer and an in-memory client for an app's tests. Cognito sends no webhooks (it runs Lambda triggers), so there is no webhook handler; password resets and email codes fail with `auth/not-supported`.
